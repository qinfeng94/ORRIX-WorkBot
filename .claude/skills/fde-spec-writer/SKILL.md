# FDE 规格撰写技能（fde-spec-writer）

## 目的

为 WorkBot 项目生成可直接评审、可直接开工的需求草案，保证每一份草案天然内嵌"不做什么"与"资金红线影响"，杜绝隐性蔓延。

## 前置动作（必须）

1. 阅读 `AGENTS.md`（红线真源）；
2. 阅读 `.fde/03-solution-design.md` 的 Non-Goals 清单与 `.fde/04-access-boundary.md` 的三色边界，确认提案不与其冲突。

## 产出模板（强制章节，缺一不交付）

```markdown
# 需求草案：<标题>
> 提案人 / 日期 / 关联文档

## 一、背景与目标（金字塔原理，结论先行）
一句话说明本提案交付什么价值、给谁用。

## 二、范围（做什么）
逐条列出交付内容，每条标注归属：Delete / Keep（确定性自动化）/ Human（人把关）/ AI（智能辅助）。

## 三、Non-Goals（明确不做清单，≥3 条）
| # | 不做什么 | 为什么不做 |
|---|---|---|
| 1 | … | … |

## 四、FIN-001 影响评估（强制）
| 检查项 | 结论 |
|---|---|
| 是否触碰付款/退款金额判断？ | 是/否 + 依据 |
| 是否存在金额边界（¥50,000）变更？ | 是/否；若有，必须列边界值用例（含 =50,000、50,001、拆单合并） |
| 是否新增/绕过具名审批环节？ | 是/否；若有，审批人是谁，AI 是否可能代签（必须为否） |
| 琥珀色预警交互是否需要更新？ | 是/否 |
| 考卷是否需要加题？ | 是/否；需加题则列出题目编号区间 |

## 五、权限边界自查
逐区核对：绿区（只读）新增了什么？黄区（人工确认）多了什么？是否触碰红区（必须为零）？

## 六、验收标准
可勾选的验收清单，引用 `.fde/05-eval-spec-20.md` 相关题号。
```

## 硬性规则

- Non-Goals 至少 3 条；FIN-001 影响评估表不得留空，任何一格都要有明确"是/否 + 依据"；
- 凡评估结果为"触碰红线"的提案，直接标注 **🔴 需三人签字（林总/王主管/陈总）后方可开发**；
- 草案语言：清晰中文大白话，禁止黑话；禁止出现"AI 自动打款"类字样（红区禁令）。
