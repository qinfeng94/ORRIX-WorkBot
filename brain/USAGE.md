# 公司大脑使用指南（brain/USAGE.md）

> 适用对象：所有 AI 编程助手与人类协作者。效力低于 `AGENTS.md`；卡片内容与代码冲突时以代码为准。

## 一、日常使用（读取侧）

1. 动手改代码前，先读 [INDEX.md](./INDEX.md)，按「卡片清单」或「按场景检索」定位**命中的单张卡**。
2. 只读命中的卡，**严禁**把 `brain/` 整目录读入上下文。
3. 卡片之间不互相引用细节，只给路径——顺着路径按需展开，避免连带加载。

## 二、更新卡片（写入侧）

### 触发时机（满足任一即更新）

- 代码落地了新决策、新红线落地方式或新排障结论；
- 发现卡片与代码不一致（以代码为准，**回写修正卡片**）；
- 排障耗时超过 10 分钟且根因不在现有「排障速查」表里。

### 更新规则

| 变更类型 | 动作 |
|---|---|
| 修正既有结论 | 直接改对应卡片，并在文末追加一行 `> 修订：YYYY-MM-DD <一句话>` |
| 补充排障经验 | 优先并入 `DOMAIN-XINGCHEN.md` §排障速查表（症状/根因/处置 三列） |
| 新增架构决策 | 按「三、新增卡片」流程建 ADR 卡 |

### 写作纪律（每张卡必须遵守）

- 单卡 ≤200 行，自带出处（原文件路径 + 证据代码路径）；
- 结论先行：每张卡开头一句话能独立回答「这条规则是什么」；
- 只写「已验证的结论」，不写猜测、不写未落库的计划；
- 涉及财务/权限的规则，必须同步引用 `.fde/` 契约编号（如 FIN-001），不私自改写口径。

## 三、新增卡片

1. **先归类**：业务规则 → 并入 `DOMAIN-XINGCHEN.md` 对应小节；架构决策（有「背景/决策/后果」三段价值）→ 新建 `ADR-00X.md`；都不属于 → 先在对话中确认是否真的值得沉淀，避免卡片膨胀。
2. **建 ADR 卡**：复制 `ADR-001.md` 的结构（状态/出处/证据 → 背景 → 决策 → 后果 → 改动守则），编号顺延，标题一句话点明取舍。
3. **登记索引**：在 `INDEX.md` 卡片清单表加一行（卡片 / 主题 / 何时读 / 一句话结论），并在「按场景检索」补对应触发场景。
4. **收口**：若新决策改变了既有红线行为，须先过 `.fde/` 契约变更流程（三人签字），再写卡片；卡片是记录，不是审批通道。

## 四、废弃卡片

- 结论被推翻时**不删文件**，把卡片头部状态改为 `已废弃（YYYY-MM-DD，被 ADR-00X 取代）`，并在 INDEX 中移除登记行——保留演变历史，防止旧结论复活。
