# ADR-004 —— 统一推理入口 `src/lib/workbot/` 收口接口设计（Day 23）

> 状态：第一步已落地（2026-11-26：六文件骨架 + 18 冒烟用例全绿，存量路由未动）；二~三步待灰度
> 溯源：[BENCHMARK-ORCHESTRATION.md](./BENCHMARK-ORCHESTRATION.md) §2 的四个散装重复点；AGENTS.md 三色权限边界；ADR-001~003 既有决策。
> 一句话：**全项目只留一个进大门的门卫（`src/lib/workbot/`），7 个既有引擎降级为门卫身后的内室，任何页面/路由不得绕过门卫私开后门。**

## 一、目标与 Non-Goals

**目标**：后续所有新增页面/路由统一走 `src/lib/workbot/` 受控核心引擎；LLM 调用、超时重试、SSE 事件、红线挂点四类横切能力只存在一份实现。

**Non-Goals（V1 明确不做）**：
- 不推倒重写 E1~E7 任何一个既有引擎（门面只包外壳，内核原样保留）；
- 不引入新的编排框架（LangGraph/LlamaIndex 等一律不评估）；
- 不改变任何既有页面的对外行为（迁移期新旧入口同构，用户无感）；
- 不把门面做成"自由对话机器人"（编排形态仍由各业务引擎决定，门面只管入口和横切能力）。

## 二、目录规划

```
src/lib/workbot/
├── types.ts          # 统一类型：WorkbotRequest / WorkbotSseEvent / WorkbotMeta
├── llm-gateway.ts    # 全项目唯一 LLM 出口（内部委托 lib/llm/llm-client.mjs，路由禁止直连）
├── resilience.ts     # 全项目唯一超时/重试/熔断策略（合并 resilientFetch 与 A2A 熔断器口径）
├── sse-envelope.ts   # 统一 SSE 事件信封 + 流式响应编解码（各引擎事件映射进统一信封）
├── guards.ts         # 红线挂点：FIN-001（复用 fin001.ts）、PII 脱敏（复用 pii-scrubber.ts）、红区自检
└── facade.ts         # 唯一门面入口 runWorkbot() / streamWorkbot()
```

## 三、核心接口（TypeScript 草图，全部禁 any）

```ts
// types.ts —— 统一请求
export interface WorkbotRequest {
  /** 业务流形态，决定由哪个内室引擎承接 */
  flow: "chat" | "investigate" | "research" | "multiagent" | "workflow";
  question: string;
  /** 会话上下文（对话流必填；其余流可省） */
  history?: readonly ConversationTurn[];
  /** 调查/研究流的定位参数（CUST-xxxx 等） */
  refs?: Readonly<Record<string, string>>;
  /** 元信息透传：提示词版本、引擎选择等 */
  meta?: Partial<WorkbotMeta>;
}

// types.ts —— 统一元信息（落审计台账的口径）
export interface WorkbotMeta {
  traceId: string;
  flow: WorkbotRequest["flow"];
  engine: string;          // 实际承接的内室引擎标识，如 "react-agent" | "inngest-fallback"
  promptVersion: string;
  zone: "green" | "yellow" | "red";
}

// types.ts —— 统一 SSE 事件信封（替代 5 套各自定义的事件类型）
export type WorkbotSseEvent =
  | { type: "phase"; label: string }                                   // 阶段开始/切换
  | { type: "step"; kind: "thought" | "action" | "observation"; step: number; payload: unknown }
  | { type: "notice"; level: "info" | "warn" | "fallback"; text: string }  // 降级/压缩/告警
  | { type: "card"; card: DryRunCard | EvidenceCard | ApprovalCard }   // 受控卡片（Dry-Run 审批/证据链）
  | { type: "text_delta"; text: string }                               // 逐字流式回复
  | { type: "usage"; meta: WorkbotMeta; ttftMs: number; costUsd: number }
  | { type: "done"; meta: WorkbotMeta };
```

```ts
// facade.ts —— 唯一入口（同步调查类）/ 唯一流式入口（对话类）
export async function runWorkbot(req: WorkbotRequest): Promise<WorkbotResult>;
export function streamWorkbot(req: WorkbotRequest, emit: (e: WorkbotSseEvent) => void): Promise<void>;
```

门面内部按 `flow` 分发到内室引擎，分发前强制过三道门卫：
1. `guards.ts` 输入侧：PII 脱敏 + 红区语义自检（复用 E1 的 RED_ZONE_BANNED_WORDS 思路）；
2. 执行侧：内室引擎只准通过 `llm-gateway.ts` 调 LLM、只准用 `resilience.ts` 的超时重试；
3. 输出侧：事件一律经 `sse-envelope.ts` 统一信封出站，卡片类型必须在受控注册表内（呼应 ADR-001）。

## 四、四类横切能力的收口规则

| 能力 | 收口后的唯一实现 | 取代的散装现状 |
|---|---|---|
| LLM 调用 | `llm-gateway.ts`（内部委托 `lib/llm/llm-client.mjs` streamChat；计费经 after() 落 llm_usage_logs） | chat / research-analyst / examiner 三处直连 import |
| 超时重试 | `resilience.ts` 导出统一档位：`probe(400ms,2 次,降级缓存)`、`external(2500ms,2 次熔断,冷却 30s)`、`llm(主备秒切)` | resilientFetch / A2A 熔断器 / llm-client 各自实现 |
| SSE 信封 | `sse-envelope.ts` 统一 7 类事件；各引擎旧事件 → 信封的映射函数写在各自引擎旁，不散在路由里 | 5 套自定义事件类型 |
| 红线挂点 | `guards.ts`：FIN-001 一律走 `fin001.ts`（含 E1 手写 50000 的整改）、PII 一律走 `pii-scrubber.ts` | E1 手写金额判断 |

**路由侧纪律（写给所有后续开发）**：
- ✅ 允许：`import { streamWorkbot } from "@/lib/workbot/facade"`；
- ❌ 禁止：路由直接 `import ... from "@/lib/llm/llm-client.mjs"`；路由直接构造各引擎私有 SSE 事件；路由各自 fetch 其它路由。

## 五、迁移路线（灰度，不搞大爆炸）

1. **第一步（✅ 2026-11-26 已完成）**：`src/lib/workbot/` 六文件就位（types / llm-gateway / resilience / sse-envelope / guards / facade），llm-gateway 与 resilience 均带启动自检（`assertGatewayHealthy` / `assertResilienceHealthy` / `assertGuardsHealthy`，`assertWorkbotHealthy` 三合一）；冒烟测试 `tests/workbot.test.ts` 18 用例覆盖档位/熔断/门卫/分发/信封；存量路由不动。实现与设计草图有一处小差异：`streamWorkbot` 签名为 `(req) => Response`（内部用 sse-envelope 的 `createWorkbotSseResponse`），比设计稿多包了一层，路由侧更省事。
2. **第二步**：新页面/新路由一律走 facade（写进 AGENTS.md 变更流程为约束项）。
3. **第三步**：存量路由按「先 examiner → 再 research-analyst → 最后 chat」灰度接入；`/api/investigate` 迁移时同步整改 E1 手写 50000 为 `fin001.ts`。
4. **每迁一个**：跑 `.fde/05` 相关考题回归，确认对外行为不变。

## 六、违规自检（如何"确保不各自为战"）

- `resilience.ts` 与 `llm-gateway.ts` 模块加载时自检：若被绕过（检测点为门面外再次 import llm-client 的静态检查脚本）则构建告警；
- 收口完成标准：全项目 grep `lib/llm/llm-client` 的**路由层直连必须为 0**（引擎内部经 gateway 委托不计入）；
- 与 ADR-003 的关系：workflow 双引擎分发逻辑保留在 `workflow/` 内部，仅其对外入口改挂 facade，状态机纪律（单点推进、幂等 409）原样继承。
