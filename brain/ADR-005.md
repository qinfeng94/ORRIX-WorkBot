# ADR-005 · AI 时代架构宪章（Harness Engineering）

- **状态**：Accepted
- **日期**：2026-11-26（Day 26）
- **承接**：ADR-001（受控组件）· ADR-002（Pre-filtering ACL）· ADR-003（审批状态机）· ADR-004（统一推理入口）
- **一句话**：Agent = 模型 + 马具。模型是发动机，马具（信息层 / 执行层 / 反馈层）才是我们能负责的那部分。

---

## 一、为什么要立这部宪章（大白话背景）

项目跑到第 26 天，代码里攒下两类“惯性负债”，不点名就会继续长大：

1. **规则长在肉里**：财务 ¥50,000 审批门槛、华东区物流条款、美元汇率 7.2 这些业务数字，
   以前散落在好几个源码文件里。财务想把 5 万调成 3 万，得改代码、走发版、等三天。
   更要命的是改漏一处，红线就悄悄漂移——AI 还以为自己很合规。
2. **工具碎了一地**：为了让模型“什么都能查”，一度堆出好几把底层小工具（查工单、查客户、查制度……）。
   工具越多，模型选错工具的概率越高，而且每次对话都要背一整套工具说明书，Token 白烧。

这两类债不是靠“写个更好的提示词”能还的，得靠架构。于是有了这份宪章。

---

## 二、核心架构决策（三层马具）

### 信息层：少给、给准、按需给

- **垂直切片**：一个需求 ≈ 一个文件夹（schema / 引擎 / 工具 / 测试），别做 6~8 层 MVC 洋葱。
- **文件黄金区间 150~400 行**：低于 40 行是碎文件（AI 修一个小需求要连读七八个文件），
  超过 600 行是上帝文件（AI 只能通读全文，烧三倍 Token）。
- **单一真源**：`AGENTS.md` 保持精简，业务卡在 `brain/`，按 `INDEX.md` 一跳命中单张卡，禁止整目录灌上下文。
- **Pre-filtering ACL**：检索先按角色过滤文档池再打分，越权内容在数学上不可达（见 ADR-002）。

### 执行层：红线写在代码里，不写在提示词里

- **规则外置**：金额门槛 / 汇率 / 区域条款 / 废止制度清单全部搬进 `config/approval-policies.json`（纯数据）。
  改规则 = 改配置，5 秒生效、源码零改动。配置里**禁止任何可执行逻辑**，全仓零 `eval()` / `new Function()`。
- **启动一致性校验**：`src/lib/fin001.ts` 保留 ¥50,000 字面量作为“锚”，与配置不符直接拒绝启动（fail-closed）。
  这不是散落副本，而是防止配置被改坏后代码静默放行的保险丝。
- **工具收敛为 3 个业务意图**：`inspect_case_bundle`（案情勘察）/ `search_compliance_policy`（制度检索）/
  `prepare_human_approval_draft`（审批预演）。按“业务意图”聚合，不按“数据库表”切碎；单工具核心入参 3~6 个。
- **红区物理剔除**：打款 / 付款 / 放款类工具**不存在于注册表**，不是靠提示词劝阻；启动自检扫描工具名与描述兜底。
- **黄区强制预演**：写操作一律 Dry-Run，只产出 Diff 草稿 + 审批单号，正式数据零改动，放行永远归具名的人。
- **金额算术 100% 确定性**：整数分四则校验，禁止模型口算汇率、禁止抹零凑平。

### 反馈层：没有考卷就不许合入

- **25 题分层阻塞式门禁**：`pnpm eval:ci`（安全 6 / 契约 6 / 容灾 6 / 推理 7），前 3 层 100% 必过，
  第 4 层 AutoSxS 胜率 ≥ 80%，25/25 全绿零退步才解锁 Merge，红灯 `exit 1` 物理锁死。
- **破坏演习**：`pnpm eval:chaos` 在内存把红线改成废止的 10 万旧制度，门禁必须当场亮红灯，
  修复后整卷转绿——证明门禁真的能拦住红线回归，而不是装饰。
- **失败即派单**：红灯自动生成 `data/evals/failure-briefs.json`，按层指派修复代理并标注必读知识卡。
- **经验反哺**：线上客诉脱敏后沉淀为新的考卷题目，写回 `brain/` 卡片，防止同一个坑踩第二次。

## 三、放弃的备选方案与权衡

| 备选 | 为什么不选 |
|---|---|
| 6~8 层 MVC / Manager / Service 洋葱分层 | AI 改一个小需求要沿链路读十几个文件，输入 Token 翻数倍；本项目是小团队+AI 协作，层级越少越好 |
| 2,000 行“全能引擎”单文件 | 一次通读成本极高、冲突频繁、无法按需检索；宁可拆成 150~400 行的垂直切片 |
| 把红线写进超长系统提示词 | 提示词不是强制约束，模型会漂移；算术与红线必须交给确定性代码，提示词只讲角色与格式 |
| 给模型 12 把细粒度 CRUD 工具 | 误选率高、说明书占 Token；实测合并为 3 个意图工具后选择面更清晰 |
| 用 `eval()` 执行配置里的规则字符串 | RCE / 原型链逃逸风险；配置只能是纯数据 JSON（规则 DSL 另立专项） |
| 跳过 CI 凭感觉合入 | 无法证明“没改坏”；25/25 阻塞门禁是唯一合并标准 |

## 四、量化实证结果（Day 26 实测，非估算）

| 指标 | 术前 | 术后 | 变化 |
|---|---|---|---|
| 五维体检总分 | 48/100（D 级） | 78/100（C 级） | +30，4/5 维度转绿 |
| 业务规则硬编码 | 4 处源码命中 | 0 处 | 改规则触碰源码 4 → 0 个文件 |
| 对话工具数 | 4 把 | 3 把 | -25% |
| 每轮输入 Token | 352 | 305 | **-13.4%** |
| 单次派发耗时 | 0.016ms | 0.018ms | 持平（亚微秒级噪声；真实 LLM 场景因说明书变短而下降） |
| 25 题 CI 门禁 | 24/25（有红灯） | **25/25 全绿** | AutoSxS 胜率 100%，零退步 |

**遗留病灶（诚实披露）**：D1 架构粒度仍为 🔴 20 分——项目里有 15 个 >600 行的上帝文件
（最严重 `app/multimodal/page.tsx` 1458 行）与 6 个 <40 行碎文件。这是历史债，
需要按“一次一个垂直切片”的方式逐步还，不在本次手术范围内，已登记为下一批整改项。

## 五、施工纪律（谁都要守）

1. 新增业务规则先问一句：这该不该是配置？该 → 写进 `config/approval-policies.json`，别写进 `if`。
2. 新增能力先问一句：这属于既有 3 个业务意图之一吗？属于 → 扩参，不要新造工具。
3. 新文件落 150~400 行；超过 600 行必须拆。
4. 任何涉及金额 / 审批 / 权限的改动，先更新 `.fde/` 契约并获签字，再动代码。
5. 改完必须 `pnpm exec tsc --noEmit` 零错误 + `pnpm eval:ci` 25/25 全绿，缺一不准合入。
6. 红线继续铁律不变：AI 只读、起草、标记；放行永远归具名在职的人；旧版 10 万制度永不复活。
