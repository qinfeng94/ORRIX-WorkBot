# ADR-001 · 生成式 UI 采用「受控组件目录」而非自由 HTML

> 状态：已采纳（Day 8 上线）· 出处：`docs/architecture/WORKBOT-PRODUCTION-ARCHITECTURE.md` §ADR-001
> 证据：`src/lib/genui/catalog-schema.ts` + `src/components/genui/ComponentRegistry.tsx`

## 背景

让大模型直接输出 UI 代码 = 把任意 JS 注入高管浏览器（提示注入、XSS、越权脚本）。AGENTS.md 代码红线明令：**严禁让大模型输出原始 HTML/JS**。

## 决策

- 模型只能输出「**白名单组件名 + 受控 Props**」的布局 JSON，前端按注册表渲染。
- 组件目录固定 **4 大类 16 组件**：
  - 指标类：`kpi_card` / `risk_banner` / `progress_bar` / `cost_card`
  - 图表类：`dept_bar_chart` / `trend_line_chart` / `share_donut_chart` / `funnel_chart`
  - 表格类：`ticket_table` / `policy_citation_card` / `customer_profile_card` / `comparison_matrix`
  - 交互回写类：`approval_form_card` / `quick_filter_bar` / `dry_run_confirm_card` / `export_report_button`
- 逐组件 Props 校验器；布局 JSON 含 `<script`、`javascript:`、`onerror=` 注入特征 → 服务端直接 400。
- 未注册组件名 → 温和降级为灰色提示条；每个组件独立 ErrorBoundary。
- 解析函数必须剥离 ```json 围栏；图表数值用 `Math.max(...values, 1)` 兜底防全零 NaN。
- `approval_form_card` 点击批准真实回写审计表并立刻刷新大屏指标。

## 后果

- 代价：牺牲表达自由度；新增组件需扩目录 + 写校验器（受控演进）。
- 收益：**模型输出永远不可能执行**的物理保证——安全不靠提示词劝阻，靠渲染层白名单。

## 改动守则

新增 UI 能力 = 在目录里注册新组件 + 写 Props 校验器，**绝不是**放开 HTML 输出。
